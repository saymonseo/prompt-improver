# Поиск и оформление Prompt Improver на GitHub

Этот документ фиксирует решения по оформлению на 6 сентября 2026 года. Он отделяет обнаружение репозитория в GitHub от выдачи внешних поисковиков и каталогов скиллов.

## Название и описание

Сохраняем `saymonseo/prompt-improver`: имя короткое, соответствует назначению и уже используется в ссылках и командах установки.

H1 русской главной страницы: **Prompt Improver: скилл для улучшения промптов**. H1 английской страницы: **Prompt Improver: an AI prompt engineering skill**. В каждом README один H1; разделы используют H2, подраздел установки — H3. Это редакторская структура страницы, не обещание повышения позиции.

Описание репозитория для поля About:

```text
AI prompt engineering skill for Codex: guided requirements gathering, context research, and ready-to-use prompts. Улучшение промптов и постановка задач для ИИ.
```

Topics:

Это метки назначения и формата. Не добавляем названия конкурентов, нерелевантные популярные темы или неподтверждённые отметки совместимости.

## Что влияет на обнаружение

В обычном поиске репозиториев GitHub по умолчанию ищет в имени, описании и topics. Для содержимого README используется `in:readme`. Поэтому один хороший H1 не заменяет заполненное описание и темы. [Документация поиска GitHub](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories).

Темы создают дополнительные пути обнаружения через тематические страницы и поиск. GitHub допускает до 20 меток, но заполнять весь лимит не требуется. [Документация topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).

README объясняет назначение, запуск и способы получить помощь. Вынесение сборки в CONTRIBUTING сокращает путь нового пользователя до первого запуска. Отдельный английский README помогает читателям; индексация обеих языковых версий и их позиции не гарантируются. [Назначение README в GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).

Для внешнего поиска полезны содержательные заголовки, ясный основной текст и естественные ссылки. Google использует несколько источников для формирования заголовка результата; многократное повторение ключей не рекомендуется. H1 внутри README не даёт владельцу репозитория прямого управления HTML-тегом `title`, метатегами, `robots.txt` или canonical самой страницы GitHub. [Рекомендации Google по заголовкам](https://developers.google.com/search/docs/appearance/title-link).

## Главная страница

В README размещены понятный первый абзац, одна локальная SVG-обложка с alt-текстом, три информативных бейджа, короткая навигация, команда установки и пример после реальных уточнений. Существенная информация остаётся текстом и не спрятана в изображении.

Раздел проверок ссылается на исходные результаты. Бейдж «18 topics» означает наличие отчёта, а не прохождение всех возможных испытаний или измеренный рост точности. На странице нет выдуманных отзывов, пользователей, оценок популярности и знака лицензии, которая не выбрана.

SVG в README является обложкой страницы. Он не устанавливает отдельное изображение Social preview: этот параметр настраивается в Settings и принимает PNG, JPG или GIF. При необходимости такую карточку можно оформить отдельно; в текущую настройку она не входит. [Документация Social preview](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview).

## Обнаружение установщиком и каталогами

Проверка 6 сентября 2026 года:

```bash
npx --yes skills@1.5.23 add saymonseo/prompt-improver --list
```

Результат: обнаружен один скилл `prompt-improver`. В проверке была отключена телеметрия; установка не выполнялась. Это подтверждает обнаружение текущей структуры, а не испытание скилла во всех поддерживаемых установщиком агентах. Флаги установки описаны в [Skills CLI](https://github.com/vercel-labs/skills).

По [FAQ skills.sh](https://www.skills.sh/docs/faq), рейтинг использует агрегированные данные установок через CLI. Наличие публичного репозитория и успешный `--list` не означают, что мы уже присутствуем в каталоге или занимаем в нём позицию. Искусственные установки и накрутка метрик не нужны.

Вне текущей редакции остаются выбор лицензии, опубликованные версионные релизы и отдельная проверка установки и поведения в дополнительных средах. GitHub API на дату обзора не определил LICENSE у нашего репозитория. Лицензию следует выбирать владельцу как отдельное решение.

## Как оценивать результат оформления

После повторного обхода поисковыми системами можно отдельно проверить брендовый запрос и тематические запросы, например `prompt-improver`, `prompt engineering skill` и «скилл для улучшения промптов». Для GitHub также полезны `user:saymonseo topic:prompt-engineering` и `prompt-improver in:name,description,readme`.

Фиксируйте дату, запрос и фактический результат, а не только наличие ключевого слова в тексте. Для посещений и клонирований используйте доступную владельцу статистику GitHub. Внешняя выдача зависит от обхода и ранжирования: оформление не гарантирует индексацию, сроки появления или место в поиске. Автоматический мониторинг этим изменением не создаётся.
