# Разработка Prompt Improver

Проверяйте изменения на наблюдаемом поведении: сохранении цели, использовании ответов, переносе ограничений и пригодности готового задания. Красивое оформление промпта само по себе не подтверждает его эффективность.

Редактируйте модульные файлы скилла. `SPECIFICATION.md` генерируется из них и не должна редактироваться отдельно. Новый предметный профиль добавляйте вместе со ссылкой из ядра, разделом в `project.json` и подходящими сценариями проверки.

## Сборка и проверки

Из корня проекта, Python 3.10 или новее:

```text
python -X utf8 tools/project.py build
python -X utf8 tools/project.py check
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tools/project.py package
```

Скрипт использует стандартную библиотеку Python, не вызывает модели, не устанавливает пакеты и не обращается к сети. `package` создаёт два архива рядом с папкой проекта: весь проект и отдельный скилл.

`check` проверяет структуру, ссылки и соответствие спецификации исходникам. Поведение модели оценивается отдельно по [протоколу](evals/PROTOCOL.md). Фактические результаты публикуются в [VALIDATION.md](evals/VALIDATION.md).

## Изменения инструкций

Сначала зафиксируйте конкретный сбой и ожидаемое поведение. После правки проверьте этот сценарий и близкие случаи, где новое правило могло помешать. Не превращайте одну ошибку в универсальный запрет.

Остановку брифинга по выбору пользователя, значимые неизвестные внутри промпта и последние исправления требований нужно сохранять. Синтетические примеры помечайте; чужие реальные данные обезличивайте.

## Изменения документации

У русской и английской главных страниц должны совпадать команды, версия и статус возможностей. Не добавляйте в README обещания, которых нет в скилле или проверках. Новые предложения из обзоров обозначайте как планы до реализации.

Для внутристраничных ссылок задавайте явные HTML-якоря: их проверяет текущий сборщик. Обложки и документацию храните вне устанавливаемой папки скилла, чтобы не увеличивать рабочий контекст модели.

При изменении версии обновляйте `project.json`, спецификацию через `build` и видимые обозначения версии в обоих README. Редакторские изменения документации не требуют новой поведенческой версии.
