# Протокол проверки 1.2.0

Дата: 6 сентября 2026 года. Цель — проверить новые инструкции и сохранение ключевых правил брифинга. Это целевой прогон, а не оценка качества на репрезентативной выборке.

## Условия

- Восемь сессий улучшателя созданы без истории разработки. Шесть читают модульный скилл и нужные ссылки; `research` и `classify` читают только единую спецификацию. Модель и reasoning effort не переопределяются; точный снимок модели не зафиксирован.
- Исполнители получают роль тестового участника: работать только с заданной инструкцией и учебным запросом, без сети и других агентов. Вопросы сохраняются как текст ответа; реальному пользователю их не отправляют. Критерии и ожидаемые результаты скрыты от исполнителей.
- `briefing` продолжается в одной сессии четырьмя последовательными репликами. Остальные случаи независимы. Полные ответы проверяет основной агент, участвовавший в разработке; независимого оценщика нет.
- Затем создаются четыре новые сессии исполнения. Им передаются только подготовленные файлы с финальным промптом и подставленным входом, без скилла, ожидаемых ответов и истории. Условия модели наследуются без переопределения.
- Проверочные значения не повторяют учебные примеры в шаблоне. Ожидаемые результаты сохранены до запуска исполнителей. Ответы сравниваются парсером и по заранее известным значениям.

## Файлы

- `actors/<случай>/user-N.txt` — дословные содержательные реплики задания; техническая обёртка запуска и локальные пути исключены.
- `actors/<случай>/answer*.md` — полные ответы улучшателя; `prompt.txt` — копируемая инструкция из ответа.
- `execution/<случай>/request.txt` — полный промпт с подставленным проверочным входом; `answer.txt` — дословный результат его исполнения.
- [expected.json](expected.json) — входы и ожидаемые значения; [results.json](results.json) — оценки, точные цитаты и SHA-256 ответов исполнителей.
- [verify_outputs.py](verify_outputs.py) — проверка сохранённых ответов; не вызывает модель и не измеряет семантическое качество новых ответов.

Переводы строк в опубликованных файлах приведены к LF в соответствии с настройкой репозитория; лишняя пустая строка в конце ответа `tools` удалена. Содержательный текст ответов не редактировался; контрольные суммы относятся к опубликованным файлам.

Чтобы повторно проверить сохранённые исполнения, из корня проекта запустите:

```bash
python evals/runs/upgrade-1.2.0/verify_outputs.py
```

Для нового модельного прогона создайте чистые сессии по тем же правилам и сохраните новые ответы отдельно. Зафиксируйте модель, настройки, дату, версии инструментов и все повторы, включая неудачные. Новый прогон не должен перезаписывать исторические ответы.

Все материалы учебные. Перед публикацией проверено отсутствие локальных путей и известных форматов секретов. Выводы и ограничения описаны в [отчёте](../../UPGRADE-1.2.0.md).
