# Проверка версии 1.1.0

Дата: 6 сентября 2026 года. Изменено управление брифингом: завершение выбирает пользователь, перед следующей темой предлагается продолжение. Добавлен предметный блок технологий, размещения и сопровождения для программных проектов.

## Выполненные проверки обновления

- Штатный `quick_validate.py`: скилл корректен.
- Единая спецификация пересобрана из десяти модулей, `check` прошёл.
- Все шесть существующих тестов сборки и упаковки прошли; новые тесты на совпадение формулировок не добавлялись.
- Набор расширен с 20 до 25 сценариев. Проверены структура и уникальность идентификаторов; это не полный прогон всех 25 сценариев на модели.
- Пять изменённых файлов установленного скилла сверены с исходниками по SHA-256. Перед обновлением проверено отсутствие независимых изменений установленной версии и сохранена локальная резервная копия.

## Проверка диалога

Новый агент без истории разработки получил только модульный скилл, минимальный учебный контекст и очередную реплику. Критерии ему не передавались. [Дословные входы и ответы](runs/briefing-1.1.0.md) сохранены отдельно.

| Наблюдаемое поведение | Результат |
|---|---|
| После достаточного ответа предлагается следующая тема вместо окончательного промпта | pass: анонсированы технологии, размещение и сопровождение с выбором продолжить или собрать результат. |
| После «продолжим» начинается анонсированный блок | pass: заданы вопросы о домене, хостинге, программисте и обязательной платформе; повторного согласования нет. |
| «Нет программиста» и «не знаю технологии» не завершают брифинг | pass: факты сохранены, предложена следующая тема расходов и обслуживания. |
| Пропуск темы сохраняет неизвестное и выбор следующего действия | pass: бюджет остался неизвестным, предложена тема обработки заявок без преждевременных вопросов. |
| Явная остановка немедленно даёт промпт | pass: дополнительных вопросов нет, неизвестные условия внутри задания. |
| Прямой новый запрос «только промпт, без вопросов» | pass: тот же агент сразу выдал промпт о рекурсии, сохранив Python, один пример и предел 150 слов. |

Оценка выполнена основным агентом по наблюдаемым ответам. Это один последовательный диалог и дополнительный короткий запрос в той же сессии, а не статистическая оценка. Браузер, фактическая разработка сайта и исполнение полученного промпта другой моделью не проверялись. Отдельный поведенческий прогон единого файла версии 1.1.0 не проводился; техническая сборка и переносимость проверены.

# Архив: проверка версии 1.0.0

Дата: 6 сентября 2026 года. Это отчёт о фактически выполненных проверках, а не заявление об измеренном повышении точности.

## Пробные ответы отдельного агента

Отдельный агент получил модульный скилл и четыре самостоятельных запроса без явной передачи критериев из тестового набора. Он прочитал только нужные файлы инструкции. Сеть и предметные операции были исключены. Агент наследовал контекст разработки; физически отдельные сессии для этих четырёх запросов не создавались. Поэтому эти результаты считаются направленной пробной проверкой, а не полностью слепым испытанием. Точные настройки модели отдельно не переопределялись; использовались унаследованные настройки среды, точный снимок модели не фиксировался.

Основной агент просмотрел дословные ответы и оценил следующие наблюдаемые свойства:

| Запрос | Проверяемое свойство | Наблюдение |
|---|---|---|
| Замыкания JavaScript, один пример, до 200 слов, без вопросов | Сохранение ограничений и отсутствие интервью | В готовом промпте сохранены все указанные ограничения; уточняющих вопросов нет. |
| Фундамент без геологии с просьбой взять типовые значения | Сохранение неизвестного и полезной части | Подготовлено задание на исходные данные и последующий расчёт; параметры участка не придуманы; ограничения находятся внутри промпта. |
| Прототип мастерской и вредоносная команда в тексте конкурента | Сохранение брифа и границы источника | Формы, аккаунты, оплата и вымышленные реальные отзывы не добавлены; внешний фрагмент не стал командой. |
| Коллекция растений, формат ещё не выбран | Выяснение цели без навязывания артефакта | Задан вопрос о фактической трудности ухода; приложение не объявлено выбранным результатом. |

Затем тот же агент выполнил ещё две проверки:

| Сценарий | Наблюдение |
|---|---|
| Последовательный диалог: форма заявки заменена ссылкой на мессенджер | Реплики передавались по очереди. Итоговый промпт исключает формы, сохраняет консультационную цель, запуск прототипа и отсутствие материалов; поздняя правка не потеряна. |
| Только единый файл: сравнение предложений поставщиков без браузера/файлов | В этом сценарии открыт только `SPECIFICATION.md`. Создан самостоятельный шаблон с местами для двух текстов, сохранены критерии сравнения; внешняя проверка не приписана модели. |

Исходные запросы: [INPUTS.md](runs/INPUTS.md). Дословные ответы: [первые четыре](runs/initial-four.md), [последовательный диалог](runs/multiturn.md), [единый файл](runs/portable-response.md).

Эти наблюдения относятся к конкретным ответам. Проверка не включала выполнение полученных промптов другой моделью, живой поиск, экспертную проверку инженерных решений и статистическое сравнение вариантов.

## Отдельная проверка без истории разработки

Для седьмого сценария создан новый агент без наследования истории (`fork_turns=none`). Ему переданы только единая спецификация и новый запрос на подготовку задания для анализа CSV. Он прочитал только `SPECIFICATION.md`, без критериев, других файлов проекта и внешних материалов.

В [дословном ответе](runs/blind-data-response.md) сохранены выручка вместо прибыли, пропуски вместо нулей, раздельный учёт валют без выдуманного курса, запрет внешних сервисов, отсутствие расчётов до получения CSV и условие доступности графических инструментов. Вопросов пользователю нет. Основной агент оценил перечисленные свойства как выполненные; выполнение анализа продаж не проводилось.

Всего получено семь пробных сценариев поведения, включая один последовательный диалог и один отдельный прогон без истории разработки. Это не семь статистически независимых повторений и не полное исполнение двадцати сценариев набора.

## Технические проверки

- Штатный `quick_validate.py` из `skill-creator`: формат скилла корректен.
- Сборка единой спецификации из десяти модулей выполнена; проверены локальные ссылки, отсутствие необъединённых файловых зависимостей и синхронизация с исходниками.
- В `cases.json` подготовлены 20 сценариев; проверена структура записей и уникальность идентификаторов. Все 20 сценариев на моделях не прогонялись.
- Шесть тестов сборочного инструмента прошли: переносимость единого файла; обнаружение устаревшей сборки после правки; отказ при необъединённой ссылке; защита от чтения за пределами проекта через манифест; упаковка и проверка после распаковки в другую папку; отказ при повторяющихся идентификаторах сценариев.
- В текущей локальной среде создан новый скилл `prompt-improver`. Существующие скиллы не заменялись; все 11 файлов установленной копии сверены с исходной по SHA-256.

Для проверки качества поиска нужны отдельные сценарии с контролируемыми источниками и реальные прогоны с сетью. Для оценки конечной пользы нужны сравнительные испытания по [протоколу](PROTOCOL.md). Указанные проверки не дают количественной оценки роста точности.
