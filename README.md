# Prompt Improver — постановка задач для ИИ

Версия 1.0.0. Пакет инструкций на русском языке. Модель помогает уточнить намерение, исследовать необходимые сведения и подготовить самостоятельный проверяемый промпт. Это проект инструкций и проверок; для использования не нужны сервер, подписка на отдельный сервис или Python. Сама выбранная модель и её инструменты предоставляются вашей средой.

## Самый простой запуск

Приложите [SPECIFICATION.md](SPECIFICATION.md) к новому диалогу с моделью, умеющей читать вложения, и напишите:

```text
Используй приложенную спецификацию как инструкцию помощника по постановке
задач для ИИ. Помоги уточнить мой замысел и подготовь готовый промпт.
Моя исходная задача: [опишите задачу своими словами].
```

Можно вставить содержимое файла в настройку инструкций помощника или в начало диалога. В пользовательской настройке оно действует в пределах правил вашей платформы. Если модель не читает вложения, вставьте текст. Исходную задачу передавайте отдельно от текста инструкции.

Вся инструкция находится в одном файле, его ссылки ведут к разделам внутри него. Для работы не требуется прикладывать этот README, историю разработки и тестовый набор. Копируемый промпт из ответа затем передаётся модели-исполнителю вместе с указанными материалами.

## Скилл

[skill/prompt-improver/SKILL.md](skill/prompt-improver/SKILL.md) — модульная версия с подключением подробностей по необходимости. Для локальной установки поместите целиком папку `prompt-improver`, включая `references` и `agents`, в каталог навыков вашей среды Codex: `$CODEX_HOME/skills`, либо `~/.codex/skills`, если `CODEX_HOME` не задан. Не перезаписывайте одноимённый пользовательский скилл без проверки его содержимого. При установленном скилле стартовый запрос:

```text
Используй $prompt-improver. Помоги подготовить промпт для моей задачи:
[опишите задачу].
```

Автоматический выбор скилла сохранён; описание ограничивает его задачами улучшения промптов и подготовки заданий. Запрос на обычное создание сайта сам по себе не должен запускать отдельное обязательное интервью.

## Что можно указать дополнительно

Свободным текстом задайте желаемую глубину, целевую модель, доступные инструменты, ограничения длины, исходные документы и допустимость вопросов. Специальный синтаксис не нужен. Например: «Проработай подробно, задавай вопросы постепенно» или «Без вопросов, подготовь черновик с неизвестными».

Если у модели нет интернета, она должна обозначить, что внешняя проверка не выполнена. Если нужны критические измерения, скилл не подставляет их из головы. В творческих задачах разрешённый вымысел сохраняется.

## Изменения и пересборка

Редактируйте модульные файлы скилла. `SPECIFICATION.md` генерируется из них и не должен редактироваться отдельно. Для новой предметной области добавьте профиль, ссылку из ядра, раздел в `project.json` и сценарии проверки. Не превращайте единичную ошибку в запрет для всех задач.

Из корня проекта, Python 3.10 или новее:

```text
python -X utf8 tools/project.py build
python -X utf8 tools/project.py check
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tools/project.py package
```

Команда `package` создаёт два архива рядом с папкой проекта: весь проект и отдельный скилл. Скрипт не делает сетевых запросов, не вызывает модели и не устанавливает ничего. Проверка `check` проверяет структуру, ссылки и соответствие единой спецификации исходникам; она не оценивает правильность ответов нейросети.

Поведенческие испытания проводятся отдельно по [протоколу](evals/PROTOCOL.md). Текущие фактически выполненные проверки отражаются в [отчёте](evals/VALIDATION.md). Наличие спецификации и успешная проверка файлов не гарантируют безошибочных ответов или измеренного роста точности.
